# FOOTORY 제품 DNA

> Last synced: 2026-04-10
> 이 문서는 Footory의 제품 방향을 고정하는 기준 문서다. 기능 제안, 기획, 디자인, 구현, 리뷰는 이 문서를 우선 기준으로 판단한다.

## 1. Footory가 풀어야 하는 문제

Footory는 유소년 축구 선수가 자신의 커리어와 실력을 더 잘 보여주기 위해 사용하는 제품이다. 핵심은 "누가 더 인기 있는가"가 아니라 "이 선수가 어떤 선수인지, 무엇을 해냈는지, 무엇을 증명할 수 있는지"를 빠르게 전달하는 것이다.

Footory는 선수를 위한 포트폴리오 제품이다. 소셜 네트워크가 아니며, 팬덤형 피드 서비스도 아니다. 제품의 모든 화면과 기능은 결국 선수의 어필, 커리어 기록, clip 기반 영상 증거, 객관 지표 전달 효율로 수렴해야 한다.

## 2. 핵심 원칙

### 2.1 선수 커리어/어필 중심

- Footory는 선수 커리어/어필 중심이다.
- 모든 주요 화면은 선수의 프로필, clip 포트폴리오, 선택형 하이라이트, 태그 포트폴리오, 객관 지표, 팀 컨텍스트를 강화해야 한다.
- 사용자가 앱을 떠난 뒤에도 남는 가치는 "이 선수를 설명할 수 있는 자료"여야 한다.

### 2.2 Evidence > Opinion

- Footory는 의견보다 근거를 우선한다.
- 인상비평, 감상, 인기, 분위기보다 영상, 기록, 태그, 이력, 출전 맥락 같은 검증 가능한 정보를 우선한다.
- 제품은 "잘해 보인다"보다 "무엇을 보여줬고 무엇이 남는가"를 구조화해야 한다.

### 2.3 Video-first, Clip-first

- Footory는 Video-first 제품이다.
- Footory의 기본 영상 단위는 하이라이트 완성본이 아니라 clip이다.
- 사용자는 짧은 clip을 빠르게 올리고, 업로드 직후 재생하고, 필요할 때만 trim, spotlight, zoom, lower third, highlight range를 적용할 수 있어야 한다.
- 하이라이트는 기본 강제 단계가 아니라 선택형 편집 기능이다.

### 2.4 Spotlight and Zoom are core playback

- 축구 영상은 멀리서 찍히는 경우가 많으므로 주인공 식별은 core다.
- spotlight와 zoom playback은 부가 효과가 아니라 선수 이해를 돕는 핵심 재생 기능이다.
- profile card와 lower third는 선수 어필을 돕는 필수 정보 장치로 유지한다.

### 2.5 Team is context, not identity

- 팀은 중요하지만 선수 정체성의 본체가 아니다.
- 팀 정보는 선수를 설명하는 맥락이어야 하며, 선수를 팀에 종속시키는 구조가 되어서는 안 된다.
- 팀 화면과 팀 기능은 선수 포트폴리오를 보강하는 수단이어야지, 팀 커뮤니티 자체가 제품의 중심이 되어서는 안 된다.

## 3. 제품이 지켜야 할 방향

### 3.1 포트폴리오 우선

- 새 기능은 최소한 아래 다섯 축 중 하나 이상에 명확히 기여해야 한다.
- 프로필
- clip 포트폴리오와 선택형 하이라이트
- 태그 포트폴리오
- 객관 지표
- 팀 컨텍스트

위 다섯 축에 기여하지 못하면, 기능 제안 단계에서 우선 보류한다.

### 3.2 영상은 "빠르게 올리고 바로 보여주는 어필 도구"여야 한다

- 영상 기능은 "예쁜 편집 앱"보다 "짧은 영상을 빠르게 올리고 선수를 바로 보여주는 구조"가 우선이다.
- 편집의 기본값은 업로드 후 바로 재생 가능이어야 하며, 하이라이트는 선택형으로 붙는다.
- spotlight, zoom playback, profile card, lower third는 결과물 장식이 아니라 core playback 기능이다.
- 효과, 장식, 배경음악, 스타일 프리셋은 선수를 더 잘 보이게 할 때만 의미가 있다.
- 사용자가 어려운 편집을 오래 배우게 만드는 방향은 지양한다.

### 3.3 팀과 소셜은 보조 수단이다

- 팀 기능은 선수 이력, 소속 맥락, 활동 배경을 설명하는 수준에서 설계한다.
- 소셜 기능은 선수 노출과 공유를 보조할 수 있지만, 제품의 주인공이 되어서는 안 된다.
- MVP 단계에서는 과도한 소셜 피드화를 금지한다.

## 4. 명시적 금지 원칙

### 4.1 피드 제품으로의 변질 금지

- MVP에서 과도한 소셜 피드화 금지.
- 체류 시간, 반응 수, 중독성 강화를 위해 무한 스크롤 피드와 반응 루프를 핵심 축으로 키우지 않는다.
- "무엇을 올리면 더 반응을 얻는가"보다 "무엇을 남기면 선수에게 도움이 되는가"를 우선한다.

### 4.2 주관 평가 기능 금지

- 주관적 평점/별점/랭킹 기능 금지.
- 인기투표, 별점, 감성 평가, 커뮤니티 평판 점수는 선수 평가의 본질을 왜곡하므로 제품 중심 기능으로 두지 않는다.
- 순위를 보여주더라도 객관적 근거와 명확한 산식 없이 서열화하지 않는다.

### 4.3 편집 앱화 금지

- 하이라이트를 모든 clip에 강제하는 구조 금지.
- 범용 숏폼 편집 앱처럼 복잡한 타임라인, 과한 장식, 효과 중심 UX로 가는 확장 금지.
- 서버 렌더나 export를 core flow처럼 다루며 기본 업로드를 느리게 만드는 방향 금지.

### 4.4 기능 확장 명분의 왜곡 금지

- "재미있어 보여서", "바이럴이 될 것 같아서", "다른 앱도 하니까"는 기능 추가 근거가 될 수 없다.
- 새 기능은 반드시 선수 어필 효율, 자료 축적 가치, 근거 기반 전달력 중 하나를 개선해야 한다.

## 5. 기능 제안 판단 질문

새 기능을 제안할 때 아래 질문 중 다수에 "예"라고 답할 수 있어야 한다.

- 이 기능이 짧은 clip 업로드와 즉시 재생을 더 쉽게 만드는가?
- 이 기능이 spotlight, zoom playback, player info overlay 같은 핵심 재생 경험을 강화하는가?
- 이 기능이 하이라이트를 강제하지 않으면서 선택형 편집의 품질을 높이는가?
- 이 기능이 선수의 프로필을 더 강하게 만드는가?
- 이 기능이 태그 포트폴리오를 더 쌓이게 만드는가?
- 이 기능이 객관 지표나 커리어 기록을 더 명확하게 보여주는가?
- 이 기능이 팀 정보를 선수 맥락으로 더 잘 연결하는가?
- 이 기능이 의견이 아니라 근거를 남기는가?

여기에 명확히 답하지 못하면, 구현 우선순위를 낮춘다.

## 6. 한 줄 정의

Footory는 유소년 축구 선수가 짧은 clip과 근거를 중심으로 자신의 커리어를 어필하는 Video-first, Clip-first 포트폴리오 제품이다.
