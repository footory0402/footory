# FOOTORY 코드 리뷰 기준

> Last synced: 2026-04-09
> 이 문서는 PR과 변경 사항이 Footory의 제품 방향을 해치지 않는지 검토하기 위한 체크리스트다.

## 1. PR/변경 검토 기준

### 1.1 문제 정의

- [ ] 이 변경이 해결하려는 사용자 문제를 한 문장으로 설명할 수 있다.
- [ ] 변경 이유가 "있으면 좋아 보임"이 아니라 실제 제품 가치와 연결된다.
- [ ] 구현 범위가 요청한 문제보다 불필요하게 커지지 않았다.

### 1.2 제품 기여도

- [ ] 이 변경은 프로필, 하이라이트, 태그 포트폴리오, 객관 지표, 팀 컨텍스트 중 하나 이상에 직접 기여한다.
- [ ] 선수 커리어/어필 중심이라는 제품 목적과 맞는다.
- [ ] 결과적으로 선수 자료의 전달력, 축적 가치, 공유 가치를 높인다.

### 1.3 근거 기반 설계

- [ ] Evidence > Opinion 원칙을 지킨다.
- [ ] 주관적 감상보다 영상, 태그, 기록, 이력 같은 근거를 강화한다.
- [ ] 객관적 설명 없이 사용자를 서열화하거나 평가하지 않는다.

## 2. 제품 DNA 위반 여부

- [ ] Footory는 선수 커리어/어필 중심이라는 전제를 흐리지 않는다.
- [ ] Team is context, not identity 원칙을 깨지 않는다.
- [ ] 팀 기능이 선수보다 앞에 오지 않는다.
- [ ] 새 기능이 포트폴리오 제품을 소셜 제품으로 변질시키지 않는다.
- [ ] MVP에서 과도한 소셜 피드화 금지 원칙을 위반하지 않는다.
- [ ] 주관적 평점/별점/랭킹 기능 금지 원칙을 위반하지 않는다.
- [ ] 새 기능이 프로필, 하이라이트, 태그 포트폴리오, 객관 지표, 팀 컨텍스트 중 어디에 기여하는지 명확하다.

## 3. 영상 UX 위반 여부

- [ ] Video-first 원칙과 맞는다.
- [ ] 영상 기능이 "예쁜 편집 앱"보다 "선수를 어필하는 하이라이트 생성"을 우선한다.
- [ ] 편집 단계가 불필요하게 길어지거나 복잡해지지 않았다.
- [ ] 시각 효과가 선수 플레이 이해를 방해하지 않는다.
- [ ] 결과물이 선수의 장면, 맥락, 강점을 더 잘 보여준다.
- [ ] 영상 UX가 범용 숏폼 편집기처럼 확장되지 않았다.
- [ ] 영상 공유 결과물이 프로필과 포트폴리오로 자연스럽게 이어진다.

## 4. 코드 품질 기준

### 4.1 단기 편법 금지

- [ ] 죽은 코드가 남지 않았다.
- [ ] 더 이상 쓰지 않는 컴포넌트, 훅, 유틸, 타입이 제거되었다.
- [ ] 임시코드가 주석이나 분기 형태로 방치되지 않았다.
- [ ] TODO, FIXME, mock, debug 코드가 근거 없이 남지 않았다.

### 4.2 토글과 분기 절제

- [ ] 임시 feature flag, 실험용 토글, 불분명한 Boolean 분기를 남발하지 않았다.
- [ ] 비슷한 화면을 토글로 억지 유지하지 않고, 필요한 경우 명확히 정리했다.
- [ ] 사용되지 않는 옵션값, 스타일 variant, 숨은 탭이 남아 있지 않다.

### 4.3 유지보수성

- [ ] 변경 의도가 코드 구조에 자연스럽게 드러난다.
- [ ] 이름이 기능 목적을 설명한다.
- [ ] 기존 구조를 더 복잡하게 만들지 않았다.
- [ ] 재사용보다 명확성이 중요한 곳에서 과도한 추상화를 하지 않았다.

## 5. 테스트와 회귀 확인

- [ ] 핵심 흐름 회귀 위험을 검토했다.
- [ ] 버그 수정이라면 재발 방지 관점의 테스트 또는 검증 근거가 있다.
- [ ] UI 변경이라면 주요 사용자 흐름에서 깨지는 지점이 없는지 확인했다.
- [ ] 영상, 프로필, 공유, 탐색 등 제품 핵심 경로에 부작용이 없는지 확인했다.

## 6. 리뷰어 최종 질문

- [ ] 이 변경이 없으면 사용자가 손해 보는 이유를 설명할 수 있다.
- [ ] 이 변경이 들어가면 Footory가 더 선명해지는지 설명할 수 있다.
- [ ] 이 변경이 제품을 더 산만하게 만들지 않는다고 자신 있게 말할 수 있다.
- [ ] 이 변경이 3개월 뒤에도 남길 가치가 있는 코드라고 판단된다.
