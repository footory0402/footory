# Footory 영상 편집 화면 흐름

## 목적
- 업로드 직후 사용자가 바로 편집에 들어가도록 화면 흐름을 단순화한다.
- 각 화면은 행동이 1개 또는 2개만 또렷하게 보이도록 설계한다.
- 기본 흐름은 `clip` 저장까지이고, `highlight`와 `reel highlight`는 그 다음 단계로 분리한다.
- 구간 자르기, 주인공 강조, 확대 재생, 선수 정보 넣기, 하이라이트는 모두 선택사항이다.

## 기본 흐름
1. 영상 선택
2. 업로드 중
3. 구간 자르기
4. 주인공 강조
5. 선수 정보 넣기
6. 저장 완료
7. 선택형 하이라이트
8. 상위 기능 릴 하이라이트

## 화면별 기준

| 화면 이름 | 사용자 목표 | 핵심 CTA | 보조 CTA | 숨길 요소 | 다음 화면으로 넘어가는 조건 |
|---|---|---|---|---|---|
| 영상 선택 | 올릴 `clip`을 고른다 | 영상 고르기 | 이어서 하기 | 하이라이트, 릴 하이라이트, 선수 정보 입력, 공개 설정, 복잡한 안내 | 영상 파일이 선택되고 길이와 용량 확인이 끝나면 업로드 중으로 이동 |
| 업로드 중 | 기다리는 동안 편집으로 바로 이어진다는 것을 안다 | 편집 준비 중 | 다른 영상 고르기 | 세부 처리 용어, 고급 옵션, 긴 상태 설명, 확장 기능 제안 | 업로드와 기본 정보 저장이 끝나면 자동으로 구간 자르기로 이동하거나 한 번의 탭으로 이동 |
| 구간 자르기 | 보여줄 시작과 끝만 고른다 | 이 구간으로 갈게요 | 다시 보기 | 선수 정보, 하이라이트 제안, 릴 하이라이트, 공개 설정, 많은 탭 | 시작과 끝이 정해지면 주인공 강조로 이동 |
| 주인공 강조 | 누가 주인공인지 정하고 필요한 만큼 가까이 본다 | 이 선수를 강조할게요 | 지금은 넘어갈게요 | 태그 입력, 공유, 릴 만들기, 복잡한 효과 이름 | 주인공 위치를 정했거나 건너뛰기를 눌렀을 때 선수 정보 넣기로 이동 |
| 선수 정보 넣기 | 필요한 정보만 짧게 넣고 가리지 않게 배치한다 | 이 정보 넣기 | 정보 없이 저장 | 긴 소개글, 여러 장식, 큰 카드, 복잡한 배치 선택 | 이름과 기본 정보 확인이 끝나면 저장 완료로 이동 |
| 저장 완료 | 편집한 `clip`을 저장하고 바로 확인한다 | 내 영상으로 저장 | 바로 보기 | 세부 편집 패널, 복잡한 공유 옵션, 릴 편집 도구 | 저장이 끝나면 선택형 하이라이트 제안 화면을 띄우거나 종료 |
| 하이라이트 만들기 | 원하면 짧은 강조 구간을 만든다 | 하이라이트 만들기 | 나중에 하기 | 릴 편집 도구, 긴 설명, 기본 편집 기능 재노출 | 사용자가 만들기를 고르면 하이라이트 구간 선택으로 이동하고, 나중에 하기를 누르면 종료 |
| 릴 하이라이트 만들기 | 여러 결과를 모아 상위 결과물을 만든다 | 릴 하이라이트 만들기 | 다음에 할게요 | 단일 `clip` 기본 편집 기능, 업로드 첫 화면 요소 | 저장된 `clip` 또는 `highlight`가 2개 이상 있을 때만 진입 가능 |

## 화면별 세부 원칙

### 1. 영상 선택
- 제목은 짧게 쓴다.
- 파일 형식과 제한은 한 줄 또는 두 줄 안에서 끝낸다.
- 첫 화면의 중심은 `영상 고르기` 하나여야 한다.

### 2. 업로드 중
- 진행 상태는 3단계 이내로만 보여준다.
- "기다리면 편집으로 이어진다"는 점만 분명하면 된다.
- 완료 후 편집 진입은 자동 이동이 기본이다.

### 3. 구간 자르기
- 사용자는 기본 구간을 그대로 두고 다음으로 넘어갈 수 있어야 한다.
- 이 화면의 중심은 시간 막대와 영상 재생이다.
- 시작과 끝을 고르는 일 외 설정은 최대한 숨긴다.
- 사용자는 지금 "어디를 남길지"만 판단하면 된다.

### 4. 주인공 강조
- 주인공 강조를 하지 않고 넘어가도 저장 흐름이 막히면 안 된다.
- 이 화면에서는 주인공 지정과 확대 재생만 다룬다.
- 주인공을 한 번 눌러 정하거나, 건너뛰고 다음으로 갈 수 있어야 한다.
- 어려운 기능 이름 대신 "주인공", "따라가기", "확대"처럼 쉬운 말만 쓴다.

### 5. 선수 정보 넣기
- 선수 정보 없이 저장하는 경로를 기본 보조 CTA로 둔다.
- 기본은 최소 정보만 넣는 것이다.
- 이름, 포지션, 등번호 정도만 우선한다.
- 미리보기에서 safe area를 함께 보여 줘야 한다.

### 6. 저장 완료
- 저장 이후 첫 선택은 `저장`과 `보기` 정도면 충분하다.
- 저장 직후 복잡한 확장 메뉴를 열지 않는다.
- 하이라이트는 카드 한 장 수준의 가벼운 제안으로만 둔다.

### 7. 하이라이트 만들기
- `highlight`는 선택형 제안이다.
- 기본 흐름을 마친 다음에만 보여준다.
- 사용하지 않아도 손해 보는 느낌을 주면 안 된다.

### 8. 릴 하이라이트 만들기
- `reel highlight`는 단일 `clip` 편집과 분리한다.
- 여러 결과가 쌓였을 때만 상위 기능으로 제안한다.
- 결과 중심으로 설명하고, 편집 도구처럼 보이게 하지 않는다.

## 상태 전이 원칙
- 업로드 완료 후 편집 진입은 자동 또는 한 번의 탭으로 끝나야 한다.
- 저장 전까지는 상단 단계 이름을 고정해 길을 잃지 않게 한다.
- 뒤로가기는 이전 단계 하나만 돌아가게 한다.
- 저장 완료 이후에만 하이라이트, 릴 하이라이트, 공유 같은 확장 행동을 제안한다.

## 가장 먼저 고쳐야 할 화면 3개
1. 업로드 중 화면: 업로드가 끝나면 바로 편집으로 이어진다는 확신이 약하다.
2. 단일 `clip` 편집 첫 화면: 기능 이름이 먼저 보이고 사용자의 첫 행동이 바로 읽히지 않는다.
3. 선수 정보 넣기 화면: 정보가 영상을 얼마나 가리는지보다 입력 요소가 먼저 보일 가능성이 크다.
