# 영상 업로드 및 편집 사양

> Last synced: 2026-04-12

## 문서 목적
- Footory에서 만들 영상 업로드 및 편집 기능의 기준 사양을 고정한다.
- 이 문서는 하이라이트 중심 문서가 아니라 clip-first 업로드와 선택형 편집 기준을 정의한다.
- 현재 살아 있는 저장 계약과 재생 계약을 버리지 않고 제품 기준을 다시 맞춘다.

## 제품 원칙
- 기본 업로드 플로우는 짧은 영상 빠른 업로드다.
- 기본 소비 플로우는 업로드 후 바로 재생 가능이다.
- 영상 편집은 선수 프로필 강화 도구여야 한다.
- 하이라이트는 후속 선택형 기능으로 두며 항상 강제되지 않는다.
- 주인공 선택, 구간 맞추기, profile card, lower third는 쉽게 접근 가능한 기본 편집 도구로 유지한다.
- 전문 편집기처럼 복잡하게 만들지 말 것.

## 사용자 목표
- 짧은 영상을 빠르게 올리고 바로 보여 주고 싶다.
- 필요할 때만 주인공, 구간, 프로필카드, 하단 선수정보를 조정하고 싶다.

## 핵심 사용자
- 부모: 촬영한 짧은 영상을 빠르게 올려 자녀 프로필에 반영하고 싶다.
- 선수: 내 clip을 바로 보여 주고, 필요한 경우에만 대표 범위를 다듬고 싶다.
- 팀 운영자: 선수별 포트폴리오 자료를 빠르게 쌓고, 과한 편집 없이 재생 가능 상태로 만들고 싶다.

## 해결하려는 문제
- 축구 영상은 멀리서 찍히는 경우가 많아 주인공 식별이 어렵다.
- 일반 편집기는 기능이 너무 많아 모바일에서 빠르게 쓰기 어렵다.
- 모든 clip을 하이라이트 완성본으로 만들도록 강제하면 업로드 속도와 유지 비용이 커진다.

## Core Flow
1. 사용자가 짧은 영상을 선택한다.
2. 시스템이 원본 업로드와 메타데이터 준비를 진행한다.
3. 업로드가 끝나면 사용자는 `이대로 저장` 또는 `편집하고 저장`을 고를 수 있다.
4. 편집을 택한 경우 주인공, 구간, 프로필카드, 하단 선수정보를 조정한다.
5. 저장 결과는 기존 clip 계약과 프로필 연결 구조 안에서 소비된다.

## 기본 업로드 플로우
- 단일 clip 업로드
- 허용 형식, 길이, 용량 제한 이해
- 업로드 진행 상태 노출
- 업로드 직후 메타데이터 추출과 썸네일 준비
- 실패 시 재시도 또는 복구 안내

## 기본 소비 플로우
- 업로드 후 바로 재생 가능
- `clips` 메타데이터 기반 런타임 재생
- spotlight와 zoom playback 적용 가능
- player profile card와 lower third 표시 가능
- 프로필 featured 후보 또는 clip 포트폴리오에서 즉시 소비 가능

## 선택 편집 플로우
- 장면 이동과 주인공 선택
- trim
- profile card 표시
- lower third 표시 제어
- 확대 재생은 `주인공 선택` 안에서 함께 조정한다.
- 편집 화면의 기본 구조는 하단 단일 타임라인 하나로 유지한다.

하이라이트는 이번 기본 플로우의 중심이 아니며, 사용자는 편집을 생략하고 clip을 그대로 저장할 수 있어야 한다.

## MVP 범위
- 짧은 원본 영상 업로드
- 업로드 직후 메타데이터 추출과 미리보기 생성
- 업로드 후 `이대로 저장` 또는 `편집하고 저장`을 고를 수 있는 흐름
- player info overlay와 lower third 유지
- 필요 시 주인공, trim, profile card, lower third를 조정할 수 있는 선택 편집
- 결과 저장 후 프로필 반영
- 실패 시 재시도와 중단 복구 안내

## MVP 비범위
- 모든 clip에 하이라이트를 강제하는 흐름
- 전문 편집기 수준 타임라인
- 멀티트랙 오디오 편집
- 장면별 고급 자막 애니메이션
- 복잡한 전환 효과와 필터 마켓
- 협업 편집
- 여러 원본 영상을 한 프로젝트에 섞는 기능
- 자유형 스티커, 도형, 드로잉, 키프레임 편집
- BGM 자동 비트싱크
- 서버 렌더 기반 export를 core flow로 복귀시키는 작업

## 편집 기능 우선순위

### Core Playback
- profile card
- lower third
- 업로드 완료 후 저장/편집 선택 가능 상태

### Optional Editing
- 장면 이동과 주인공 선택
- 확대 재생 조정
- trim 시작/종료 조정
- player info overlay 조정
- profile card 표시 제어
- lower third 표시 제어

### Phase 2
- 서버 렌더 export
- 별도 결과물 엔티티
- clip 다중 조합 편집

## UX 원칙
- 업로드 전보다 업로드 후 행동이 더 단순해야 한다.
- 사용자는 업로드가 끝나면 바로 저장할지, 편집하고 저장할지 이해할 수 있어야 한다.
- 주인공, 구간, 프로필카드, 하단 정보는 어렵지 않게 찾고 조정할 수 있어야 한다.
- 하이라이트는 기본 저장 흐름을 막지 않는 후속 기능으로 남겨 둔다.
- 저장 전에도 미리보기는 충분히 제공해야 한다.

## 필요한 UI/UX 화면과 목적

### 1. 업로드 시작 화면
- 목적: 짧은 clip 선택과 제한 안내
- 포함 요소: 파일 선택, 허용 규격, 업로드 시작 CTA, 최근 작업 복구 진입

### 2. 업로드 처리 화면
- 목적: 업로드와 메타데이터 준비를 명확히 전달
- 포함 요소: 단계형 진행 상태, 예상 대기, 실패 시 재시도

### 3. 저장/편집 선택 화면
- 목적: 사용자가 `이대로 저장` 또는 `편집하고 저장`을 바로 고르게 함
- 포함 요소: 간단한 미리보기, 저장 CTA, 편집 CTA, 다른 영상 선택

### 4. 선택 편집 화면
- 목적: 필요한 경우에만 주인공, trim, profile card, lower third를 조정
- 포함 요소: 프리뷰, 하단 단일 타임라인, 시작/끝 조정, 원하는 시점의 주인공 선택, profile card 토글, lower third 토글

## 확대 재생 정책
- 확대 재생은 독립 편집 기능이 아니라 `주인공 강조`의 일부다.
- 사용자는 먼저 영상에서 주인공을 한 번 누르고, 필요할 때만 확대 정도를 간단히 조정한다.
- 기본 확대값은 선수 한 명이 더 잘 보이는 타이트한 값으로 둔다.
- 확대 조정은 `넓게`, `기본`, `가깝게` 같은 쉬운 선택과 핀치 정도만 허용한다.
- 사용자는 `zoom` 값을 편집한다고 느끼기보다, `주인공이 잘 보이게 맞춘다`고 느껴야 한다.
- 확대 재생은 저장 후 실제 clip 재생과 최대한 같은 구도로 보여야 한다.
- `freeze_at`가 있으면 편집 미리보기와 저장 후 재생 모두 같은 시점에서 2초 멈췄다가 다시 재생해야 한다.

### 이번 단계에서 허용하는 확대 방식
- 단일 `spotlight_x`, `spotlight_y`와 `focusZoom` 기준의 고정 확대
- 필요 시 `freeze_at` 기준의 짧은 강조
- 편집 화면에서의 간단한 확대 미리보기와 확대 정도 조정

### 이번 단계에서 하지 않을 확대 방식
- 시간에 따라 중심점이 바뀌는 추적형 확대
- `effects.trackingPoints`를 실제 사용자 편집 기능으로 노출하는 것
- 구간별 다른 확대값 저장
- 재생 중 사용자가 영상을 좌우로 옮겨 다시 구도를 잡게 하는 인터랙션
- 키프레임 기반 팬/줌 편집

### 5. 저장 확인 화면
- 목적: 프로필 반영 위치와 저장 결과를 확인
- 포함 요소: 미리보기, draft 저장 상태, featured 후보 저장 여부, 태그 연결, 실패 복구 안내

### 6. 최근 작업 복구 진입
- 목적: single clip draft 또는 reel highlight draft를 다시 열어 이어서 편집
- 포함 요소: 최근 draft 요약, 복구 CTA, publish 전 상태 안내

## 화면 설계 원칙
- 편집을 건너뛰어도 clip 소비가 완료되도록 설계한다.
- 메인 업로드에서는 선수 프로필 편집 진입과 영상 선택 진입을 함께 둘 수 있다.
- 영상 편집 안에서는 전체 프로필 편집보다 영상 내 표시 제어를 우선한다.
- 오버레이 설정은 독립적으로 유지하되 옵션 수를 적게 유지한다.
- 프로필카드가 켜진 경우에는 본영상보다 먼저 카드가 끝나고 나서 본영상이 시작돼야 한다.

## 데이터 모델 관점에서 필요한 편집 결과
- 원본 영상 식별자
- `trim_start`
- `trim_end`
- `highlight_start`
- `highlight_end`
- `duration_sec`
- `spotlight_x`
- `spotlight_y`
- `freeze_at`
- `effects.trackingMode`
- `effects.trackingPoints`
- player info overlay 설정
- 프로필 반영 대상 정보
- draft/project 식별자
- draft 상태와 published 상태 구분 값

## 프로필 반영 규칙
- 저장된 clip은 선수 프로필의 clip 목록 또는 featured 후보에 연결된다.
- 하이라이트 범위를 설정해도 기본 엔티티는 clip이다.
- 프로필에서는 clip 재생을 우선 보여 주고, highlight range는 선택형 정보로 소비한다.

## 현재 구현과의 관계
- 현재 저장소의 살아 있는 메인 계약은 `clips` 메타데이터 기반 클라이언트 재생이다.
- 본 문서는 그 구조를 버리고 새 렌더 파이프라인으로 갈아타는 문서가 아니다.
- `render-worker/`와 `/api/render/*`는 즉시 core로 복귀시키지 않고 phase 2 판단 대상으로 둔다.

## 이번 단계에서 만들지 않을 것
- 방송용 수준의 화려한 패키지 에디터
- 세밀한 색보정
- 장면별 자막 애니메이션 편집기
- 고급 오디오 믹서
- 컷마다 별도 효과 프리셋을 쌓는 기능
- 데스크톱 편집툴 같은 긴 타임라인과 다중 트랙 인터페이스

## 지금 먼저 필요한 화면 3개
- 업로드 시작 화면
- 업로드 처리 화면
- 저장/편집 선택 화면

## 나중에 미룰 화면 3개
- 서버 렌더 export 화면
- 다중 clip 조합 하이라이트 화면
- 배경음악 선택 화면
