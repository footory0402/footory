# Footory 영상 UX 원칙

## 목적
- Footory 영상 경험을 인스타그램, 틱톡처럼 짧고 바로 이해되는 흐름으로 다시 잡는다.
- 사용자는 업로드를 마치면 바로 편집에 들어가고, 바로 저장하거나 나가야 한다.
- 편집 화면에서 사용자는 지금 해야 할 행동을 1개 또는 2개 안에서 바로 이해해야 한다.

## 제품 기준
- 기본 영상 단위는 `clip`이다.
- 사용자는 `clip`을 올린 뒤 바로 편집에 들어갈 수 있어야 한다.
- 편집의 핵심 기능은 구간 자르기, 주인공 강조, 확대 재생, 선수 정보 넣기다.
- `highlight`는 선택형이다.
- `reel highlight`는 저장된 `clip`이나 `highlight`를 모아 만드는 상위 기능이다.
- 기본 흐름은 `clip` 저장까지이며, 그 이후에만 확장 기능을 제안한다.

## 핵심 방향

### 1. 업로드 후 바로 편집
- 업로드 완료 뒤 별도 탐색 없이 바로 편집 첫 화면으로 이어진다.
- 사용자는 업로드가 끝났을 때 다음 행동을 다시 고를 필요가 없다.
- 편집 첫 화면은 "무엇부터 하면 되는지"를 한 번에 이해하게 해야 한다.

### 2. 한 화면에 행동은 1개 또는 2개
- 한 화면의 핵심 행동은 1개, 많아도 2개까지만 둔다.
- 핵심 행동 외 기능은 숨기거나 다음 단계로 넘긴다.
- 한 화면에서 자르기, 강조, 정보 넣기, 공개, 하이라이트를 동시에 요구하지 않는다.

### 3. 영상이 먼저 보인다
- 화면의 중심은 항상 영상이다.
- 편집 도구보다 영상이 먼저 크게 보여야 한다.
- 안내, 설명, 배지, 카드보다 플레이 확인이 먼저 가능해야 한다.

### 4. 짧고 쉬운 한국어만 쓴다
- 영어, 기술 용어, 내부 구현 용어를 사용자 화면에 쓰지 않는다.
- 긴 설명보다 짧은 행동 문구를 쓴다.
- 사용자가 눌러야 할 버튼 이름은 바로 행동으로 읽혀야 한다.

### 5. 기본 흐름과 확장 흐름을 분리한다
- 기본 흐름은 `clip` 업로드, 편집, 저장이다.
- `highlight`는 저장 후 또는 저장 직전의 선택형 제안으로만 보여준다.
- `reel highlight`는 단일 `clip` 편집 화면 안에 섞지 않는다.

## 편집 구조 원칙

### 첫 편집 화면
- 사용자가 가장 먼저 해야 할 일 하나를 보여준다.
- 보조 안내는 한 줄이면 충분하다.
- 첫 진입에서 복잡한 탭 구조나 다중 패널을 열어두지 않는다.

### 하단 조작 영역
- 하단 고정 영역에는 현재 단계의 핵심 CTA 하나를 둔다.
- 보조 CTA는 한 개만 허용한다.
- 단계 이름과 뒤로가기 외 상단 정보는 최소화한다.

### 미리보기 방식
- 결과를 설명으로 말하기보다 영상 위 미리보기로 보여준다.
- 사용자가 변경한 내용은 즉시 영상 안에서 확인돼야 한다.
- 저장 전 미리보기에서 이미 결과가 거의 확정돼 보여야 한다.

## 편집 기능 원칙

### 구간 자르기
- 구간 자르기는 기본값을 그대로 두고 바로 넘어갈 수 있는 선택사항이다.
- 사용자는 "어디부터 어디까지 보여줄지"만 결정한다.
- 시간 막대 외 다른 설정은 이 화면에서 최대한 숨긴다.

### 주인공 강조
- 주인공 강조는 필요할 때만 켜는 선택사항이다.
- 사용자는 누가 주인공인지 고르거나 강조를 건너뛸 수 있어야 한다.
- 확대 재생은 주인공 강조와 함께 다루는 보조 기능으로 둔다.
- 강조는 복잡한 효과가 아니라 보기 쉽게 만드는 보조 수단이어야 한다.

### 선수 정보 넣기
- 선수 정보 넣기는 기본적으로 생략 가능해야 한다.
- 이름, 포지션, 등번호처럼 짧은 정보만 우선한다.
- 여러 줄 소개, 긴 경력, 큰 카드형 정보는 기본 흐름에서 다루지 않는다.
- 선수 정보는 영상 소개가 아니라 플레이 보조 정보다.

### 하이라이트
- `highlight`는 기본값이 아니다.
- 저장 흐름을 막지 않는 선택형 제안이어야 한다.
- "지금 꼭 해야 한다"는 느낌을 주면 안 된다.

## 선택형 편집 원칙
- 기본 편집 항목은 모두 선택사항이다.
- 사용자는 아무 것도 바꾸지 않고 바로 저장할 수 있어야 한다.
- 각 편집 화면에는 항상 `넘어가기`, `그대로 둘게요`, `정보 없이 저장`처럼 흐름을 막지 않는 선택지가 있어야 한다.
- 선택형 편집을 하지 않았다고 덜 완성된 영상처럼 느끼게 하면 안 된다.

### 릴 하이라이트
- `reel highlight`는 단일 영상 편집보다 위 단계에 있다.
- 여러 결과가 쌓였을 때만 제안한다.
- 저장 전 기본 편집 화면에서는 꺼내지 않는다.

## 선수 정보 오버레이 원칙

### 기본 원칙
- 선수 정보 오버레이는 영상을 돋보이게 해야지, 가리면 안 된다.
- 플레이 시야 보존이 선수 정보 노출보다 우선이다.
- 공, 주인공, 수비 흐름이 많이 지나가는 중앙 구역은 비워 둔다.

### 안전 영역
- 상단은 화면 높이 기준 12% 안쪽만 사용한다.
- 하단은 화면 높이 기준 18% 안쪽만 사용한다.
- 좌우는 각 6% 이상 비워 둔다.
- 중앙 60% x 60% 구역은 기본 금지 구역으로 둔다.

### 배치 원칙
- 기본 위치는 하단 왼쪽이다.
- 하단 왼쪽이 가려질 때만 하단 중앙 가까운 낮은 위치로 옮긴다.
- 상단 카드와 하단 정보는 동시에 크게 띄우지 않는다.
- 한 번에 한 종류의 정보 상자만 보여준다.

### 크기 원칙
- 한 줄 또는 두 줄 안에서 끝나는 짧은 정보만 허용한다.
- 화면 너비의 40%를 넘는 넓은 카드형 정보는 기본 금지다.
- 영상 높이의 18%를 넘는 큰 정보판은 사용하지 않는다.

### 표시 원칙
- 반투명 배경이나 얇은 배경판을 기본으로 쓴다.
- 두꺼운 테두리, 강한 그림자, 큰 면적 배경은 피한다.
- 플레이가 복잡한 순간에는 자동으로 더 짧게 보이거나 숨길 수 있어야 한다.

## 문구 원칙
- 제목은 행동형으로 쓴다.
- 보조 문구는 한 줄로 끝낸다.
- 에러 문구는 원인보다 다음 행동을 먼저 알려준다.
- 불필요한 약속, 과장, 전문 용어를 쓰지 않는다.

## 하지 말아야 할 것
- 한 화면에 편집 기능 3개 이상을 동시에 열어두기
- `Trim`, `Spotlight`, `Overlay`, `Highlight` 같은 영어 버튼 그대로 쓰기
- "세부 옵션을 조정할 수 있습니다" 같은 긴 설명 쓰기
- 선수 정보 카드가 영상 중앙을 덮게 두기
- 저장 전부터 공유, 공개, 모아보기 하이라이트를 같이 요구하기

## 문서 적용 우선순위
- `/upload` 업로드 완료 직후 진입 화면
- 단일 `clip` 편집 첫 화면
- 구간 자르기 화면
- 주인공 강조 및 확대 재생 화면
- 선수 정보 넣기 화면
- 선택형 `highlight` 제안 화면
