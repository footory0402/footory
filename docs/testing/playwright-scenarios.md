# 영상 하이라이트 Playwright 시나리오

## 문서 목적

- 이 문서는 영상 하이라이트 MVP를 검증하기 위한 Playwright 회귀 시나리오 기준을 정의한다.
- 시나리오는 정상 동작보다 실패, 지연, 작은 화면에서 사용자가 다음 행동을 바로 알 수 있는지를 먼저 검증한다.
- 모든 시나리오는 모바일 뷰포트를 기본값으로 두고, 데스크톱은 예외 조건일 때만 다룬다.

## 공통 테스트 원칙

- 기본 뷰포트는 모바일 화면으로 설정한다.
- 사용자 앱 회귀는 모바일 시나리오를 먼저 통과시킨 뒤 데스크톱 확인으로 확장한다.
- 선수 계정과 부모 계정은 분리해 관리하되, 핵심 happy path는 선수 계정을 기본으로 둔다.
- 실제 업로드 비용과 외부 의존성을 줄이기 위해 네트워크 모킹 전략을 문서화한다.
- 업로드 성공만 보지 말고 실패, 지연, 재진입 복구, 저장 후 프로필 반영까지 확인한다.
- 테스트 이름은 사용자 행동 기준으로 쓴다.
- 온보딩, 가이드, 하단 CTA가 함께 있는 화면은 스크린샷 검증을 포함한다.

## 권장 공통 사전조건

- 로그인된 테스트 계정
- 재현 가능한 테스트용 영상 파일
- 모바일 뷰포트 프리셋
- 업로드, 분석, 저장 API에 대한 성공/실패/지연 모킹
- 프로필 화면에서 방금 저장한 결과를 찾을 수 있는 테스트 데이터 규칙

## 시나리오 목록

### 1. Happy Path

- 목적: 업로드부터 자동 제안 확인, 컷 조정, 저장, 프로필 반영까지 한 흐름이 끊기지 않는지 확인한다.
- 사전조건: 로그인된 선수 계정, 테스트 영상 파일, 모바일 뷰포트, 성공 응답 모킹
- 핵심 단계:

1. `/upload` 진입
2. 유효한 영상 선택
3. 업로드 및 처리 상태 확인
4. 자동 하이라이트 후보 리스트 확인
5. 한 컷의 시작 또는 종료 조정
6. 대표 장면 확인 또는 지정
7. 최종 저장
8. 프로필 이동 또는 프로필 재진입

- 핵심 검증:
- 상태 표시가 단계별로 보인다
- 자동 제안 컷이 노출된다
- 컷 조정 결과가 반영된다
- 저장 성공 안내가 보인다
- 프로필에서 방금 저장한 결과를 볼 수 있다

### 2. 업로드 실패

- 목적: 네트워크 또는 업로드 단계 실패 시 사용자가 복구 경로를 이해하는지 확인한다.
- 사전조건: presign 또는 PUT 요청 실패 모킹, 모바일 뷰포트
- 핵심 단계:

1. 영상 선택
2. 업로드 시작
3. 업로드 실패 응답 발생
4. 실패 안내 확인
5. 재시도 또는 다시 선택 동선 수행

- 핵심 검증:
- 실패 원인 또는 실패 단계가 드러난다
- 재시도 버튼 또는 다시 선택 버튼이 보인다
- 사용자가 다음 행동을 이해할 수 있다
- 불완전한 저장 결과가 프로필에 반영되지 않는다

### 3. 렌더링 지연

- 목적: 분석 또는 결과 생성이 지연될 때 사용자가 멈춘 화면으로 느끼지 않는지 확인한다.
- 사전조건: 분석 또는 저장 후 처리 응답 지연 모킹, 모바일 뷰포트
- 핵심 단계:

1. 영상 업로드 성공
2. 분석 또는 처리 단계 진입
3. 지연 상태 유지
4. 대기 중 안내 확인
5. 완료 후 다음 단계 진입

- 핵심 검증:
- 업로드 중과 분석 중 상태가 구분된다
- 대기 안내 문구가 보인다
- 사용자가 기다려야 하는지 다시 시도해야 하는지 헷갈리지 않는다
- 처리 완료 후 흐름이 정상 복귀한다

### 4. 모바일 작은 화면

- 목적: 320px 전후 작은 화면에서도 핵심 조작이 가능한지 확인한다.
- 사전조건: 작은 모바일 뷰포트, 짧은 영상 파일
- 핵심 단계:

1. `/upload` 진입
2. 영상 선택
3. 후보 확인 화면 진입
4. 컷 조정 화면 진입
5. 저장 화면 진입

- 핵심 검증:
- 주요 버튼이 가려지지 않는다
- 고정 하단 액션이 영상 또는 입력을 덮어쓰지 않는다
- 가로 스크롤 없이 핵심 정보가 보인다
- 터치 타깃이 너무 작지 않다

### 5. 편집 취소 후 재진입

- 목적: 중간에 이탈한 사용자가 다시 돌아왔을 때 작업을 이어갈 수 있는지 확인한다.
- 사전조건: 일부 컷 조정 또는 대표 장면 선택까지 진행된 상태, 모바일 뷰포트
- 핵심 단계:

1. 업로드 후 후보 확인까지 진행
2. 컷 조정 일부 수행
3. 뒤로가기 또는 이탈
4. 다시 `/upload` 또는 복구 경로 진입
5. 초안 복구 또는 재개 선택

- 핵심 검증:
- 취소 시 경고 또는 복구 안내가 나온다
- 재진입 시 이전 작업 상태를 이어갈 수 있다
- 복구하지 않을 경우 초기화 동작이 명확하다

### 6. 저장 후 프로필 반영 확인

- 목적: 최종 저장 결과가 실제 프로필 경험으로 연결되는지 확인한다.
- 사전조건: 저장 성공 응답, 로그인 상태, 프로필 접근 가능
- 핵심 단계:

1. 저장 완료
2. 프로필로 이동하거나 직접 프로필 진입
3. 방금 저장한 결과 탐색
4. 결과 재생

- 핵심 검증:
- 결과가 featured 후보 또는 하이라이트 목록에 연결된다
- 프로필에서 재생 진입이 가능하다
- 저장 직후와 재진입 후 모두 결과를 확인할 수 있다

### 7. 권한 가드

- 목적: 업로드 권한이 없는 사용자가 잘못된 상태에 빠지지 않는지 확인한다.
- 사전조건: 업로드 권한 없는 계정 또는 비로그인 상태
- 핵심 검증:
- 로그인 또는 홈 이동 경로가 명확하다
- 업로드 흐름이 시작되지 않는다

### 8. 제한 초과 파일

- 목적: 길이 또는 용량이 제한을 넘는 파일에서 사용자에게 이유와 다음 행동이 명확한지 확인한다.
- 사전조건: 제한 초과 파일
- 핵심 검증:
- 제한 사유가 노출된다
- 다시 선택 경로가 바로 보인다
- 다음 단계로 진행되지 않는다

## 현재 E2E와의 불일치

### `tests/e2e/upload-wizard.spec.ts`

- 현재 파일은 인증 가드와 일부 API 응답 검증 중심이다.
- `/api/render` 같은 실험 흔적 경로까지 포함하고 있어 다음 MVP acceptance 기준과 직접 맞지 않는다.
- 사용자 기준 happy path, 실패 복구, 저장 후 프로필 반영 검증이 부족하다.

### `tests/e2e/video/video-upload-flow.spec.ts`

- 현재 파일은 `꾸미기 -> 태그 -> 효과 -> 공유` 구형 흐름을 전제로 작성되어 있다.
- 실제 업로드를 비용 때문에 수행하지 않아 저장 이후 흐름을 검증하지 않는다.
- 자동 하이라이트 제안, 렌더링 지연, 재진입 복구, featured 반영 확인 시나리오가 없다.

### `tests/e2e/video/video-player.spec.ts`

- 프로필 재생과 플레이어 동작 검증으로는 유효하다.
- 그러나 업로드와 편집 acceptance를 대신할 수는 없다.
- 저장 후 프로필 반영 확인 시나리오의 마지막 단계 검증용으로만 연결하는 편이 맞다.

## 권장 리팩터링 방향

- 기존 `video-upload-flow.spec.ts`는 구형 꾸미기 탭 기준 검증을 걷어내고, 하이라이트 MVP 기준 시나리오로 재작성한다.
- `upload-wizard.spec.ts`는 인증/API 가드 smoke test로 축소하거나 별도 파일로 분리한다.
- 저장 후 프로필 반영 확인은 업로드 시나리오와 플레이어 시나리오를 이어 주는 회귀 테스트로 분리한다.
- 작은 화면, 실패, 지연, 재진입 복구는 독립 시나리오로 유지한다.

## 구현 전 체크리스트

- 시나리오가 현재 구현 검증인지 다음 MVP 검증인지 명확한가
- 모바일 뷰포트가 기본으로 설정되어 있는가
- 성공, 실패, 지연 응답 모킹 전략이 준비되어 있는가
- 저장 후 프로필 반영을 확인할 테스트 데이터 규칙이 있는가
